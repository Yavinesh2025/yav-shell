# YAV Shell 0.2.1

YAV Shell is a console application for Windows in which two models of your choice work on your code:
**Model A** implements, **Model B** reviews independently, your project's required checks run alongside,
and only a candidate that passed all of it is offered for applying. YAV contains no model and no coding
agent: it drives the agent programs you have installed (Codex CLI, Claude Code) through their documented
interfaces, with the accounts they are signed in to.

This version makes YAV ready to use after the choice of the models: the first request asks fewer
questions, and while an agent thinks or works, the shell shows that it does.

## What is new

* **Fewer questions on the first request.** You decided on 2026-10-08 what a first request still asks:
  * **The models** are asked for once, on the first request, by number, and remembered, as in 0.2.0.
  * **An account route through a subscription** the agent is signed in to - the ChatGPT plan of Codex,
    the Claude subscription of Claude Code - is used without a typed `yes`. The run shows the route it
    uses, and a run whose agent reports another route than the one shown still stops. **A route that
    bills an API key per token still needs your typed `yes`**, as in 0.2.0 (`/login <provider>`).
  * **Checks are no longer a question.** A first request in a project without an approved required
    check runs right away, and its candidate is accepted on Model B's review alone; every such run says
    so. Where YAV finds checks it could propose, it names them in one line, with how to approve them
    (`/test detect`). YAV never runs a command of the project that you have not approved.
    `/quality gates required` makes checks required again, and a project with an approved required
    check runs it as before.
  * The folder of the project, an exact effort that YAV cannot rank (`ultra`), the sign-in of Codex and
    files that Git ignores and that would be missing from the isolated copy are asked for as in 0.2.0,
    and only when a request needs them.
* **Progress is visible while an agent thinks or works.** While a run is active, the shell shows a line
  that moves, with the time since the stage began and what is happening: which stage the run is in and
  what the agent reports it is doing. It never shows a percentage or a forecast. The line is drawn only
  in a console; `yav run`, JSON output and redirected output get no such line.
* **Codex asks less.** A command that only reads, and a change of files inside the isolated copy, are
  allowed without asking. A command that can write, chain, redirect or run code, every `git` and `rg`
  command, network access and anything outside the copy are still asked about.
* **Corrected:** Claude Code as Model A was offered its `AskUserQuestion` tool, which opens a window of
  questions that YAV cannot show, so the turn waited for an answer nobody could give. Claude Code is no
  longer offered that tool; it writes a question it has into its answer instead.

## Install

1. Download `yav.exe` and `yav.exe.sha256` from the assets of this release. Two more assets are
   optional: `YAV-Shell-0.2.1-Documentation-and-User-Guide.docx`, the documentation and user guide as
   a Word document, and `YAV-Shell-Specification.txt`, the specification YAV Shell was built to.
   `yav.exe` needs neither; it installs the documentation as Markdown files next to itself.
2. Check the download, as below.
3. Run `yav.exe` and answer `Y`. An installation of 0.2.0 or 0.1.1 is updated.
4. Install at least one agent, the way its vendor recommends, and sign in with it:

   ```powershell
   powershell -ExecutionPolicy ByPass -c "irm https://chatgpt.com/codex/install.ps1 | iex"   # Codex CLI, then: codex login
   irm https://claude.ai/install.ps1 | iex                                                   # Claude Code, then: claude auth login (or start claude and sign in)
   ```

5. Open a new PowerShell window in the folder of a project, type `yav`, and type what you want done.

The [user guide](https://github.com/Yavinesh2025/yav-shell/blob/v0.2.1/docs/user-guide.md) describes the
installation, the first request and the commands.

## Check the download

`yav.exe` is not code-signed, so Windows cannot tell you who built it. Before you start it:

```powershell
(Get-FileHash .\yav.exe -Algorithm SHA256).Hash.ToLowerInvariant()   # has to be the hash in yav.exe.sha256
Get-Content .\yav.exe.sha256
# with the GitHub CLI, signed in:
gh attestation verify yav.exe --repo Yavinesh2025/yav-shell --signer-workflow Yavinesh2025/yav-shell/.github/workflows/release.yml --source-ref refs/tags/v0.2.1 --deny-self-hosted-runners
```

The last line checks the record GitHub made when the release workflow of this repository built the
file from the tag v0.2.1 on a GitHub-hosted runner; it fails for a file that was changed afterwards
or built by another workflow, from another ref or anywhere else.

Windows SmartScreen may stop a downloaded `yav.exe` the first time with "Windows protected your PC";
"More info" and then "Run anyway" start it. On a PC where Smart App Control is on, Windows does not
start an unsigned program at all, however it is started, and `yav.exe` cannot be used there.

## What was verified, and what was not

* The automated tests (`scripts\test.ps1`), which use a scripted stand-in for the agents, so that no
  test asks a model: 2696 of 2696 passed on 2026-10-08, on the Windows 11 PC on which 0.2.1 was made.
* That the tests can fail (`scripts\mutation-check.ps1`): the 19 entries that are new for
  0.2.1 were run on the final code, and the tests noticed all 19.
* The package where there is no .NET, no Git and no agent (`scripts\verify-package.ps1`): 29 of 29 checks.
* The package on a new Windows, in Windows Sandbox (`scripts\verify-package.ps1 -Sandbox`): 37 of 37 checks.
* That the installed agents answer as YAV expects, without inference (`scripts\test.ps1 -Live`): not run for 0.2.1.
* **One small task was worked on by real models, with your authorization** (`scripts\live-run.ps1`, the
  task `01-small-edit`, Codex `gpt-6-astra` implementing and Claude Code `opus` reviewing, both on a
  subscription): it ended ready to apply after 262 s, was applied, and every check of the task passed.
  Two earlier attempts with 0.2.1 stopped because Codex asked first to run a command that only reads and
  then to change files of the isolated copy; both are now allowed without asking. The line that shows
  progress and the tool that Claude Code is no longer offered were tested against the scripted stand-in only.
* The checks above were made on Windows 11 x64. The package checks were made with a `yav.exe` built on that PC, SHA-256
  `5330608e3f2fc1385c0866067ef2197f46403f0a6f3e8fb3a38c7a0b05e6315b`. The release workflow builds `yav.exe` again from the tag, on Windows Server 2025,
  and the section "This build" below gives its SHA-256 and says what was run on it. Windows 10 and
  Windows on ARM were not tried.

[What was verified and what was not](https://github.com/Yavinesh2025/yav-shell/blob/v0.2.1/docs/verification.md)
is the full record. The section "This build" below says what the release workflow tested and checked
for this file on GitHub's runner.
