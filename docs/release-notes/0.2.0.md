# YAV Shell 0.2.0

YAV Shell is a console application for Windows in which two models of your choice work on your code:
**Model A** implements, **Model B** reviews independently, your project's required checks run alongside,
and only a candidate that passed all of it is offered for applying. YAV contains no model and no coding
agent: it drives the agent programs you have installed (Codex CLI, Claude Code) through their documented
interfaces, with the accounts they are signed in to.

This version makes YAV one program that installs itself: run `yav.exe`, type `yav` in PowerShell, and
type what you want done.

## What is new

* **Installed by running `yav.exe`.** The package is one file. It brings the .NET runtime along and
  carries the license, the notices, the documentation and the examples. Double-clicked, or started
  without arguments in a console, it offers to install itself for your user account, without
  administrator rights: `Y` (or Enter) installs, `N` starts YAV without installing it. It also runs
  without being installed, from wherever it is.
* **`yav install` and `yav uninstall`.** `yav install [--dir <path>] [--no-path] [--no-register]`
  installs without asking, by default into `%LOCALAPPDATA%\Programs\YavShell`, and lists YAV Shell
  under "Installed apps". `yav uninstall [--dir <path>] [--remove-data]` removes
  what the installation put there, its PATH entry and its entry under "Installed apps", and leaves
  anything else in the directory where it is. Your data in `%LOCALAPPDATA%\YavShell` stays unless you
  add `--remove-data`, which asks you to type `yes` and removes the data directory only when it holds
  nothing that YAV did not create and no other YAV uses it. "Installed apps" in the settings of Windows
  removes YAV Shell as well. An installation of 0.1.1 is updated by `yav install` and removed by
  `yav uninstall`; a Start menu entry it made stays, for you to delete.
* **`yav` works in every console opened after the installation.** The installation adds its directory
  to the PATH of your user account, unless you say `--no-path`. A console that was open before does
  not know the new PATH yet; the installation prints the line that makes `yav` work in it.
* **The first request guides you.** When a request cannot start for a reason only you can settle, the
  shell asks right there: for the folder of the project, for Model A and Model B (by number, from the
  models the agents list for your accounts), for an exact effort where the listed ones cannot be
  ranked, whether YAV may use the account each agent is signed in to, which commands of the project
  may run as its required checks, and whether files that Git ignores may be missing from the isolated
  copy. Where Codex is not signed in, it offers Codex's own sign-in; for Claude Code it says how to sign
  in and starts nothing. Whatever grants something needs a typed `yes`. Your answers
  are recorded the way the commands record them, and the same request is sent again. `yav run`, and
  input from a pipe or a file, ask nothing, as before.
* **Review only, for one project.** A project with no approved check that is required - YAV has no
  check to propose for it, you declined what it proposed, or what you approved requires none - can be
  accepted on the review alone, for that project only. Approving a check that is required makes checks
  required again, and `/quality gates required` withdraws the acceptance.
* **Corrected:** a request that changes no file ends as Completed ("Answered. No source was changed,
  so there is nothing to apply."). In 0.1.1 such a run was left in the state Checking, with an error.
* **Replaced:** 0.1.x was a folder of files with PowerShell scripts that installed and removed it
  (`install.ps1`, `uninstall.ps1`) and an Inno Setup script that was never compiled. They are gone.

## Install

1. Download `yav.exe` and `yav.exe.sha256` from the assets of this release. Two more assets are
   optional: `YAV-Shell-0.2.0-Documentation-and-User-Guide.docx`, the documentation and user guide as
   a Word document, and `YAV-Shell-Specification.txt`, the specification YAV Shell was built to.
   `yav.exe` needs neither; it installs the documentation as Markdown files next to itself.
2. Check the download, as below.
3. Run `yav.exe` and answer `Y`.
4. Install at least one agent, the way its vendor recommends, and sign in with it:

   ```powershell
   powershell -ExecutionPolicy ByPass -c "irm https://chatgpt.com/codex/install.ps1 | iex"   # Codex CLI, then: codex login
   irm https://claude.ai/install.ps1 | iex                                                   # Claude Code, then: claude
   ```

5. Open a new PowerShell window in the folder of a project, type `yav`, and type what you want done.

The [user guide](https://github.com/Yavinesh2025/yav-shell/blob/v0.2.0/docs/user-guide.md) describes the
installation, the first request and the commands.

## Check the download

`yav.exe` is not code-signed, so Windows cannot tell you who built it. Before you start it:

```powershell
(Get-FileHash .\yav.exe -Algorithm SHA256).Hash.ToLowerInvariant()   # has to be the hash in yav.exe.sha256
Get-Content .\yav.exe.sha256
# with the GitHub CLI, signed in:
gh attestation verify yav.exe --repo Yavinesh2025/yav-shell --signer-workflow Yavinesh2025/yav-shell/.github/workflows/release.yml --source-ref refs/tags/v0.2.0 --deny-self-hosted-runners
```

The last line checks the record GitHub made when the release workflow of this repository built the
file from the tag v0.2.0 on a GitHub-hosted runner; it fails for a file that was changed afterwards
or built by another workflow, from another ref or anywhere else.

Windows SmartScreen may stop a downloaded `yav.exe` the first time with "Windows protected your PC";
"More info" and then "Run anyway" start it. On a PC where Smart App Control is on, Windows does not
start an unsigned program at all, however it is started, and `yav.exe` cannot be used there.

## What was verified, and what was not

* The automated tests (`scripts\test.ps1`), which use a scripted stand-in for the agents, so that no
  test asks a model: 2612 of 2612 passed on 2026-10-07, on the Windows 11 PC on which 0.2.0 was made.
* That the tests can fail (`scripts\mutation-check.ps1`): 456 defects were put into the code one at a
  time, 112 of them in what is new for 0.2.0; the tests noticed all 456.
* The package where there is no .NET, no Git and no agent (`scripts\verify-package.ps1`): 29 of 29 checks.
* The package on a new Windows, in Windows Sandbox, installed with the PATH entry and the entry under
  "Installed apps" and removed again (`scripts\verify-package.ps1 -Sandbox`): 37 of 37 checks.
* That the installed agents answer as YAV expects, without inference (`scripts\test.ps1 -Live`): not run for 0.2.0.
* **No run with real models was made with 0.2.0.** YAV has made two runs of one small task with real
  models, with 0.1.0 and 0.1.1; 0.2.0 changes how YAV is installed and how the first request is set
  up. The adapters for the agents are unchanged since 0.1.1. A run after it has started changed in
  two places, apart from the wording of a message: a request that changes no file ends as Completed,
  and a candidate accepted on the review alone is not applied once that acceptance was withdrawn.
* The checks above were made on Windows 11 x64. The two checks of the package were made with a
  `yav.exe` built on that PC (SHA-256 `4f19327b057874b1d314006e3f27df5cab1ff138988d3c18164a05f4512b11cb`),
  not with the `yav.exe` of this release: the release workflow builds that file again from the tag,
  on Windows Server 2025, and the section "This build" below gives its SHA-256 and says what was run
  on it. The `yav.exe` of this release was not run in Windows Sandbox. Windows 10 and Windows on ARM
  were not tried.

[What was verified and what was not](https://github.com/Yavinesh2025/yav-shell/blob/v0.2.0/docs/verification.md)
is the full record. The section "This build" below says what the release workflow tested and checked
for this file on GitHub's runner.
